{# The watch-folder section: what settings.html includes, and what POST /settings/watch, /settings/watch/{id} and /settings/watch/{id}/delete return to swap in its place. Context (from scribe.web.settings.watch_context): watch_folders [{id, path, enabled, missing, outside_roots, unwatchable, summary}] every row, switched off ones included. Three of those keys say a folder is listed but not actually being read from, and each gets a badge next to the path: `missing` (not on this machine right now), `outside_roots` (the browse roots no longer cover it, so nothing here is read at all) and `unwatchable` (the observer would not open a watch on it - the startup walk still finds files, live events do not). `watch_context` always fills all three; they are still read with `.get` so a test that builds a row by hand renders rather than raising. quiesce_seconds how long a file must hold still before it is taken in watch_options the defaults the add-form opens with languages [(code, name)] sorted by name flash a line for the page's status region, or none oob whether this is a fragment response carrying the flash out of band Paths are rendered as text; nothing here is |safe. The diarize checkbox is preceded by a hidden diarize=0 for the same reason as everywhere else: an unticked box posts nothing at all, and the route takes the last value. #}
