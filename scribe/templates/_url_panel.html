{# What a pasted link turns out to be. POST /transcribe/url/preview (a POST because it opens a socket - see scribe.web.ingest_ui) returns it and the URL field swaps it in as it is typed (hx-target="#url-preview", hx-swap="outerHTML"). Context (from scribe.web.ingest_ui.url_preview): preview {state: "ok"|"error"|"empty", …} ok: kind ("single"|"playlist"), title, uploader, duration (seconds or none); for a playlist also entries ([{title, duration, timestamp, state, value}]), count, total (or none), truncated, feed_url, feed_title, cap (the most one import may queue) error: message - the reason, in words; retry - whether to offer the patient listing empty: message - the hint under an empty field Everything on show came back from a stranger's web page and is escaped by the environment like every other string in this app. The page URL yt-dlp reports is deliberately not rendered: the only thing to do with a URL in a template is make it a link, and autoescaping quotes an href correctly while doing nothing about a javascript: scheme. The feed's URL is echoed back only as a hidden field's value, which is an attribute and not a link. The list is the picker (TASK-021). Each row's checkbox carries the entry as JSON in its value; the browser posts the ticked ones back to /transcribe/url, which queues one job each. The row button beside the field hides while a list is on screen (app.css, :has(.episodes)), so there is one import action and it honours the ticks. Every button this panel renders is type="button" - All shown, None, the patient retry - because the panel is swapped into the dialog's form, where an untyped button is a submit that Enter presses and that app.js treats as "close the dialog" on the 200 the preview always returns. The one submit is Import, with the row button's own attributes (formaction for scripting off, hx-params="not files" so chosen files stay out of the post). The filter input carries no name: the server never sees it. The retry names both fields in hx-params. htmx 2.0.10 filters after merging hx-vals, so an allow-list of "url" alone would drop `patient`; and `patient` cannot ride on the field's own trigger, which posts with hx-params="url". hx-sync on the field and on this button means a keystroke during a patient listing aborts it in the browser and the new link previews; without it the first of two answers wins and the second is dropped. #}
