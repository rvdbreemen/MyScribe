Context (from scribe.web.exports_ui.dialog_context): bulk whether this is a selection posting to /media/bulk targets [{id, title, has_transcript}] the recordings to export action_url /media/{id}/export, or /media/bulk with action=export preview_url /media/{id}/export/preview of the first target that has a transcript, or none when none has formats [{name, label, extension}] the registry, in order presets [{name, label, options_json, builtin}] for the select options ExportOptions - the values the fields open with choices {field: (values...)} for the Literal fields default_path the folder the recording lives in written, skipped, folder set by export.html after a plain write-to-folder; the fragment ignores them One form, three doors, all posting these same fields: * Download is the form's own submit - a plain post, on purpose, because a file (or a ZIP) has to reach the browser as a navigation and htmx cannot swap one in. The response is an attachment, so the page stays. * Write to folder is a submit button with its own hx-post: htmx posts the form with destination=folder and puts the list of written files into #export-result. Without scripting the same button posts natively and the route answers with this dialog as a page. * Save preset posts the fields to /settings/presets (formaction without scripting, hx-post with) and gets the preset select back with the new one chosen; the settings page lists and deletes them. The preview pane posts the form to preview_url when it loads and whenever any field changes (hx-trigger "change from:closest form"); hx-sync replaces a request still in flight, so the pane always shows the latest fields - a preset applied by app.js fires one change after filling them. Each checkbox that stands for a boolean option is preceded by a hidden field of the same name carrying 0: an unticked box posts nothing, and the route takes the last value it sees. The format checkboxes share one name and are read as a list. Field names are ExportOptions' own, so the same parser serves every door. The dialog is marked data-stay-open: app.js closes other dialogs after a successful post from inside them, and here every preview is one. #}
