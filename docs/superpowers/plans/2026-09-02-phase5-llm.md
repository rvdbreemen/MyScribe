# MyScribe — Phase 5: LLM Layer Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ask a language model about a transcript — summarize it, pull out action items, chapter it, chat with it — through one seam that speaks to OpenAI, OpenRouter or a local Ollama model, with a private-mode pin that makes "this text never leaves the machine" enforceable rather than aspirational.

**Architecture:** One `chat()` function in `scribe/llm/`. OpenAI and OpenRouter share the OpenAI SDK (same wire format, different `base_url`); Ollama gets its native `/api/chat` so `num_ctx` and `keep_alive` are settable. Prompts are Jinja templates with a version string; outputs are stored per `(media, kind, provider, model, prompt_version)` so a better model later is a new row, never an overwrite. Long transcripts go through a map-reduce that runs as a resumable job on the existing runner. Local inference takes the same GPU lease a transcription does, so it can never fight Whisper for VRAM.

**Tech Stack:** `openai` (Python SDK, new pin), `httpx` (already present) for Ollama, Jinja2, pydantic. No new JS.

**Spec:** `docs/superpowers/specs/2026-09-01-myscribe-design.md` (section 6)

**Depends on:** Phase 3 (web, settings, `render.py`) and Phase 4 (the transcript rail this hangs actions on). Phase 4's `TranscriptDoc` loader is reused as the prompt's input.

## Global Constraints

- Phase 1–4 Global Constraints apply verbatim. ADR-001 still holds: **the web process never runs inference.** Every LLM call happens in a runner child, as a job. The web process only enqueues, reads rows, and streams stored text.
- Exactly one provider abstraction. A new provider is a `Provider` subclass plus a registry entry — never an `if provider ==` in a caller.
- **Private mode is fail-closed.** When a media (or its folder) is pinned private, any attempt to send its text to a non-local provider raises `llm.PrivacyRefused` before a request is built. This is asserted by a test that would fail if the check were removed.
- **Key resolution is one function, `llm.api_key(conn, provider)`, with a fixed order**: the `setting` table first (what the user typed in the app), then the provider's environment variables in the order listed below. First non-empty wins, and the settings page shows *which* source answered so a stale environment variable cannot silently outrank a key the user just typed.
  - OpenAI: `OPENAI_API_KEY`
  - OpenRouter: `OPENROUTER_TOKEN`, then `OPENROUTER_API_KEY` (this machine has the first one set, machine-wide)
- A key stored via the settings page lands in `setting` as plain text in `myscribe.db`. That is the honest trade for a single-user localhost app — the same threat model as the gitignored `.env` — and the UI says so in one line next to the field rather than implying a vault. Keys are never logged, never rendered back (the field shows `••••` plus the source), and never included in an error message or an `llm_output` row.
- A key must never leave the machine except to its own provider: no key is sent as a query parameter, and the OpenRouter attribution headers (`HTTP-Referer: http://127.0.0.1:4242`, `X-Title: MyScribe`) carry no user content.
- Every response is recorded with the exact `(provider, model, prompt_version)` that produced it, plus token counts when the API reports them.
- A local model holds the GPU lease: the `llm` job type runs through the same supervisor queue as `transcribe`, so at most one of them touches the card.
- Tests never make a network call. `Provider` implementations are exercised against a fake transport; exactly one GPU-marked test per provider may talk to a real endpoint, and it skips when unreachable.

## File Structure (new in Phase 5)

```
scribe/llm/
  __init__.py      # chat(), PROVIDERS registry, PrivacyRefused
  base.py          # Provider ABC, ChatRequest/ChatResponse, retry + error mapping
  openai_like.py   # OpenAI and OpenRouter (one class, two configs)
  ollama.py        # native /api/chat
  privacy.py       # is_private(media), assert_allowed(provider, media)
  chunking.py      # token estimate, split on segment boundaries, map-reduce plan
  tasks.py         # the six preset outputs: templates + schemas + runner
  prompts/         # summary.md action_items.md chapters.md minutes.md blog.md custom.md
  chat_tool.py     # chat-with-transcript: retrieval + citation parsing
scribe/stages/llm_stage.py   # the `llm` job type's stages
scribe/web/ai_ui.py          # rail actions, output panels, chat panel
scribe/templates/_ai_panel.html  _ai_output.html  chat.html
tests/test_llm_*.py
```

### Task 1: `base.py` + `openai_like.py` — the seam and the cloud providers

**Files:**
- Create: `scribe/llm/__init__.py`, `scribe/llm/base.py`, `scribe/llm/openai_like.py`, `tests/test_llm_providers.py`
- Modify: `requirements.txt` (`openai`)

**Interfaces:**
- `base.ChatRequest(system: str, user: str, model: str, temperature: float = 0.2, max_output_tokens: int = 4000, json_schema: dict | None = None)`; `base.ChatResponse(text: str, model: str, provider: str, prompt_tokens: int | None, completion_tokens: int | None, raw_finish_reason: str | None)`.
- `base.Provider` ABC: `name: str`, `is_local: bool`, `available(self) -> tuple[bool, str]` (ready?, why not), `models(self) -> list[str]`, `complete(self, req: ChatRequest) -> ChatResponse`.
- `base.LlmError` with subclasses `AuthError`, `RateLimited`, `ModelNotFound`, `ContextTooLong`, `BadResponse`, `Unreachable` — every provider maps its own failures onto these so callers never catch a vendor exception.
- `openai_like.OpenAIProvider` / `openai_like.OpenRouterProvider`: one implementation, differing in `name`, `base_url`, key names, default model and extra headers. Uses `client.chat.completions.create`. Three hard-won rules, each with a test: (1) never carry a model name across providers on fallback — model ids are provider-scoped; (2) a 200 response whose body is an error envelope or whose `choices` is empty is a `BadResponse`, not a success; (3) strip provider-specific keys the other does not accept.
- **OpenRouter specifics, measured against the live API on 2026-09-02** (probe run from this repo; the key came from `OPENROUTER_TOKEN`):
  - `base_url = "https://openrouter.ai/api/v1"`; headers `HTTP-Referer` and `X-Title` are sent for attribution.
  - `GET /models` returned **423 models**, including the `openai/`, `anthropic/` and `google/` namespaces and a set of `:free` ids. `models()` reads this endpoint, so the settings dropdown is populated from what the account can actually reach rather than a hard-coded list.
  - `openai/gpt-4o-mini` answered a one-word question in **1.8 s** (25 prompt / 2 completion tokens).
  - **`anthropic/claude-3.5-haiku` returned HTTP 404 `"No endpoints found"`** while `anthropic/claude-haiku-4.5` exists. A plausible-looking model id is not a valid one, and this is the exact failure `ModelNotFound` is for: the message names the id and the settings page offers the live list instead of free text.
  - Default model for OpenRouter: `openai/gpt-5.6-luna` — 1,050,000-token context at $0.20/M in and $1.20/M out, so an hour of transcript (~13k tokens) costs well under a cent and a four-hour recording still fits in one call without chunking. `anthropic/claude-sonnet-5` (1M context, $2/$10) is the quality option; `openai/gpt-4o-mini` ($0.15/$0.60, 128k) the cheap one. All three verified present on this account.
- Retry: `base.with_retry(fn, attempts=3)` — exponential backoff on `RateLimited` and `Unreachable` only; never on `AuthError` or `BadResponse`.
- [ ] **Step 1: failing tests** (fake transport injected as `client_factory`) — a normal completion returns text and token counts; HTTP 401 → `AuthError` and no retry; 429 → `RateLimited` and exactly 3 attempts; a 200 with `{"error": {...}}` → `BadResponse`; empty `choices` → `BadResponse`; a 404 naming a model → `ModelNotFound` carrying the id (the `anthropic/claude-3.5-haiku` case); `available()` reports False with a readable reason when no key is found; `OpenRouterProvider.base_url` is openrouter's, its default model is not OpenAI's, and it sends the two attribution headers; `api_key` resolution order is setting → `OPENROUTER_TOKEN` → `OPENROUTER_API_KEY`, the settings value wins over both env vars, and the resolved *source name* is reported without the value.

- [ ] **Step 3: implement**
- [ ] **Step 4: run** → PASS
- [ ] **Step 5: commit** `feat(llm): provider seam with OpenAI and OpenRouter behind one interface`

### Task 2: `ollama.py` + `privacy.py` — the local provider and the fail-closed pin

**Files:**
- Create: `scribe/llm/ollama.py`, `scribe/llm/privacy.py`, `tests/test_llm_ollama.py`, `tests/test_llm_privacy.py`
- Modify: `scribe/db.py` (migration v3: `media.private INTEGER NOT NULL DEFAULT 0`, `folder.private INTEGER NOT NULL DEFAULT 0`)

**Interfaces:**
- `ollama.OllamaProvider(host="http://127.0.0.1:11434")`, `is_local = True`. `complete()` posts to `/api/chat` with `{"model", "messages", "stream": false, "options": {"temperature", "num_ctx"}, "keep_alive": "5m"}`; `models()` reads `/api/tags`; `available()` distinguishes "not running" from "running, model not pulled". `num_ctx` is set explicitly per request — measured on this machine, a 12B model with a large advertised context still fails on a ~32k prompt when `num_ctx` is left at its default, so the value the request asks for is the value the caller gets or `ContextTooLong` is raised.
- `privacy.is_private(conn, media_id) -> bool` — the media's own flag, or any ancestor folder's, via the existing `WITH RECURSIVE`.
- `privacy.assert_allowed(conn, media_id, provider) -> None` — raises `PrivacyRefused` when `is_private` and `not provider.is_local`. Called at the top of `llm.chat()`, before any request object exists.
- `llm.chat(conn, *, media_id, provider_name, request) -> ChatResponse` — resolves the provider from `PROVIDERS`, asserts privacy, calls with retry.

### Task 3: `chunking.py` — fitting a transcript in a context window

**Files:**
- Create: `scribe/llm/chunking.py`, `tests/test_llm_chunking.py`

**Interfaces:**
- `chunking.estimate_tokens(text) -> int` — deliberately pessimistic (3 chars/token), same reasoning as the hotword budget: erring short costs a chunk boundary, erring long costs a failed call.
- `chunking.plan(doc, *, budget_tokens: int, overlap_segments: int = 1) -> list[Chunk]` — `Chunk(index, start, end, text, segment_ids)`. Splits **on segment boundaries only**, never mid-sentence; carries `overlap_segments` of context into the next chunk; each chunk's text is timestamped (`[m:ss] text`) so the model can cite times.
- `chunking.needs_chunking(doc, budget_tokens) -> bool`.
- `chunking.MAP_REDUCE_PROMPTS` — the chunk-level and combine-level prompt names, so `tasks.py` reads them rather than spelling them.
- [ ] **Step 1: failing tests** — a doc under budget yields one chunk equal to the whole transcript; over budget yields chunks each under budget; every chunk starts at a segment start; overlap repeats exactly N segments; time ranges are contiguous and cover the whole media; a single segment larger than the budget yields that segment alone with a recorded `oversized=True` rather than an exception.

- [ ] **Step 3: implement**
- [ ] **Step 4: run** → PASS

### Task 4: `tasks.py` + prompts + the `llm` job type

**Files:**
- Create: `scribe/llm/tasks.py`, `scribe/llm/prompts/*.md`, `scribe/stages/llm_stage.py`, `tests/test_llm_tasks.py`
- Modify: `scribe/runner.py` (register `STAGES["llm"]`), `scribe/db.py` (migration v4: `llm_output` gains `run_id`, `prompt_tokens`, `completion_tokens`, `params_json`; index on `(media_id, kind)`)

**Interfaces:**
- Six kinds, each a Jinja template plus a pydantic schema: `summary` (paragraph + bullets), `action_items` (list of `{text, owner, evidence_ts}`), `chapters` (list of `{start, title}`), `minutes` (agenda/decisions/actions), `blog` (title + markdown body), `custom` (free prompt, plain text).
- `tasks.PROMPT_VERSION = "1"` — bumped whenever a template changes; part of the stored key.
- `tasks.run_task(conn, *, media_id, kind, provider_name, model, custom_prompt=None, on_progress) -> int` — returns the `llm_output.id`. Chunks when needed: each chunk is a `chat()` call reporting progress, then one combine call. Every intermediate chunk result is stored as `llm_output` with `kind=f"{kind}:chunk:{i}"` so a resumed job skips completed chunks.
- `llm_stage.STAGES = [("prepare", …), ("generate", …), ("store", …)]` and the job params `{media_id, kind, provider, model, prompt?}`.
- Schema-constrained decoding: when the provider supports `response_format={"type":"json_schema"}` it is used; otherwise the prompt asks for JSON and the result is parsed with a repair pass (strip code fences, find the outermost object) before validating — a validation failure is `BadResponse` and the job fails with the raw text in `error_detail`.
- [ ] **Step 1: failing tests** (fake provider) — each of the six kinds produces a validated object and one `llm_output` row with the right key; a long doc produces N chunk rows plus one final row; re-running with the same `(kind, provider, model, prompt_version)` adds a **new** row and leaves the old one (no overwrite); a resumed job with existing chunk rows makes only the missing calls; a model returning fenced JSON is repaired; a model returning prose where JSON was required fails as `BadResponse` with the text preserved.
- [ ] **Step 2: run** → FAIL
- [ ] **Step 3: implement**
- [ ] **Step 4: run** → PASS
- [ ] **Step 5: commit** `feat(llm): six preset outputs as resumable map-reduce jobs`

### Task 5: `chat_tool.py` — chat with a transcript, citations that seek

**Files:**
- Create: `scribe/llm/chat_tool.py`, `tests/test_llm_chat.py`
- Modify: `scribe/db.py` (migration v5: `chat_message(id, media_id, role, content, citations_json, created_at)`)

**Interfaces:**
- `chat_tool.context_for(conn, media_id, question, *, budget_tokens) -> tuple[str, list[int]]` — the whole timestamped transcript when it fits; otherwise FTS5 retrieval over `segment_fts` scoped to the current run, taking the top segments plus one neighbour either side, in time order. Returns the context text and the segment ids used.
- `chat_tool.ask(conn, *, media_id, question, provider_name, model, history: list[dict]) -> ChatAnswer` — `ChatAnswer(text, citations: list[float])`. The system prompt requires citations as `[m:ss]`; `chat_tool.parse_citations(text) -> list[float]` extracts them and drops any outside the media duration (a hallucinated timestamp must not produce a seek to nowhere).
- Runs as an `llm` job of kind `chat`, so it obeys the same queue and privacy rules; the answer is stored as a `chat_message` pair.
- [ ] **Step 1: failing tests** — a short transcript is passed whole; a long one triggers retrieval and the returned segment ids match the FTS hits plus neighbours, in time order; `parse_citations` reads `[1:23]` and `[01:02:03]`, ignores `[abc]`, and drops a timestamp past the duration; the stored pair round-trips; a private media refuses a cloud provider here too (the same `assert_allowed` path).

### Task 6: The UI — rail actions, output panels, chat, provider settings

**Files:**
- Create: `scribe/web/ai_ui.py`, `scribe/templates/_ai_panel.html`, `_ai_output.html`, `chat.html`, `tests/test_web_ai.py`
- Modify: `scribe/templates/transcript.html` (AI section in the rail), `scribe/web/settings.py` + `settings.html` (provider defaults, availability table, private-mode default), `scribe/templates/_media_rows.html` (a private badge)

**Interfaces:**
- Rail: an "AI" section listing the six kinds; each is a `POST /media/{id}/ai/{kind}` that enqueues an `llm` job and swaps in a pending panel that polls `GET /media/{id}/ai/{kind}` every 2 s until a row exists, then renders it (markdown → HTML via a small allowlist renderer, never `|safe` on model output).
- A provider/model `<select>` on the panel, defaulting to the `setting` values; a **red "leaves your machine" marker** next to every non-local option and a lock icon when the media is private (in which case the cloud options are disabled and the form refuses server-side too).
- `POST /media/{id}/private` toggles the pin; `POST /folders/{id}/private` toggles it for a folder.
- `GET /media/{id}/chat` — the chat panel: history, a question box, answers with `[m:ss]` rendered as seek links reusing the transcript's `data-start` handler.
- Settings: a provider table (name, local?, available?, why not, default model, **key source** — `settings` / `OPENROUTER_TOKEN` / `OPENAI_API_KEY` / none) built from `PROVIDERS`; defaults saved to `setting`; a "test this provider" button that enqueues a one-token `llm` job.
- Per provider, a key field: shows `••••` plus the source when a key resolves, accepts a new one (stored in `setting`, plain text — the row says so), and offers "clear" to fall back to the environment. The model dropdown is populated from the provider's live `models()` when it is reachable, with the current value kept as a free-text fallback when it is not — so a 404 like `anthropic/claude-3.5-haiku` is impossible to pick in the first place.

## Self-review (done at authoring time)

- Spec §6 coverage: one `chat()` seam (T1, T2), OpenAI + OpenRouter via the SDK and Ollama natively with `num_ctx`/`keep_alive` (T1, T2), commercial default with a private-mode pin and a visible indicator (T2, T6), six preset outputs with schemas (T4), map-reduce for long transcripts as resumable jobs (T3, T4), chat with timestamp citations that drive the player (T5, T6), GPU semaphore via the existing queue (T4, constraint), storage per (kind, provider, model, prompt_version) (T4).
- ADR-001 upheld: inference only in runner children; the web layer enqueues and reads.
- Type consistency: `ChatRequest`/`ChatResponse` from T1 used everywhere; Phase 4's `TranscriptDoc` is the input to `chunking.plan` and `chat_tool.context_for`.
- Deliberate omission: no key management beyond environment variables. Encrypting secrets at rest for a single-user localhost app is theatre; the setting rows hold provider and model names only, and the UI says where the key lives.
